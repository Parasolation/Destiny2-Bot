# 守护者助手 · QQ 官方机器人 Windows 版

命运 2 PVP / PVE 战绩、突袭 / 地牢、对局战报、生涯、配装、成就 / 称号 / 收藏、公开周活动，以及武器、Perk、Starside 推荐和图样进度；另有玩机器热门与实时弹幕。所有查询均以图片回复：战绩、装备、图样采用本机生成的 JPEG 长图，其他提示采用 PNG，通过 QQ 官方富媒体接口上传发送。

这是独立开发的初版，与“小日向”没有隶属关系，也不是其完整功能复刻。

当前版本 **0.5.1**。与小日向公开教程的功能对照及仍未实现的项目见 [FEATURES.md](FEATURES.md)。从 0.4 或更早版本升级需要重新运行 **05-sync-destiny.cmd**；0.5.0 升至 0.5.1 只需更新源码并重启。

## 当前阶段与本机预览

已在开发用 Windows 电脑完成真实接口、中文数据库同步和 QQ 群内图片回复验证，详细记录见 [VERIFICATION.md](VERIFICATION.md)。另一台笔记本的安装与持续运行仍待验证；当前发布源码，尚未打包交付。

按下方步骤安装后，双击 **07-local-demo.cmd**，输入 `热门`、`随机`、`实时` 等指令，可以生成真实查询图片；实时预览采集 30 秒，不向 QQ 发消息。终端会打印图片路径，文件保存在 `output/`。也可运行 `node scripts/local-demo.js "热门"`。命运 2 查询需先同步数据库；个人绑定和锻造查询在 QQ 群内使用。

仓库仅提供空白配置模板，不包含凭证、生成图片、运行日志、游戏数据库、依赖或浏览器。每台电脑需要独立安装并填写自己的 `config.json`。

## Windows 安装与启动

1. 克隆 [本仓库](https://github.com/Parasolation/Destiny2-Bot)，或通过 **Code → Download ZIP** 下载并完整解压到一个固定目录，例如 `D:\GuardianBot`。不要直接在压缩包内运行。
2. 安装 [Node.js 24 LTS Windows 版](https://nodejs.org/en/download)，保留 npm 和添加 PATH 的选项。目标为 Windows 10 / 11；本项目要求 Node.js 22 或更新版本。
3. 双击 **01-install.cmd**。它会在项目目录安装锁定版本的依赖和 Chromium，并运行本地测试。首次需要下载浏览器，等待时间取决于网络。下载失败可直接重新运行，不会覆盖你的配置。
4. 双击 **02-configure.cmd**，在记事本打开的 `config.json` 中填写下面三项并保存：

   ```json
   "qq": {
     "appId": "你的 QQ 机器人 AppID",
     "appSecret": "你的 QQ 机器人 AppSecret",
     "allowedGroupIds": []
   },
   "bungie": {
     "apiKey": "你的 Bungie API Key",
     "language": "zh-chs"
   }
   ```

   以上为字段示例，不是完整配置。保留原文件其他字段，使用英文双引号，不添加注释。密钥只留在笔记本本地，不要发送到聊天、群或公共仓库。

5. 双击 **05-sync-destiny.cmd**，下载并生成本地命运 2 数据库，包括武器、Perk、属性、图样、目标、收藏证章、活动和赛季定义。首次会下载较大的官方物品表。成功后保存在 `data/`，以后武器与 Perk 查询直接检索本地数据。游戏大版本更新后再次运行，并重启机器人。升级至 0.5 时也需重新同步，以加入活动、装备、成就、收藏和公开里程碑目录；现为十一张官方定义表。
6. 双击 **04-preview.cmd**，在 `output/` 查看帮助卡片和标记为“演示数据”的样式预览。预览不登录 QQ，也不发群消息。
7. 双击 **03-start.cmd**，等待“QQ 已连接”。在已经配置好的测试群中 **@机器人 帮助**。

只想先试 6657 时可以暂不填 Bungie API Key，跳过第 5 步；命运 2 指令会以图片说明尚未配置。

## 官方账号准备

### QQ

- 在 [QQ 开放平台](https://q.qq.com/) 创建机器人应用，取得 AppID、AppSecret。使用的是机器人应用凭证，不是个人 QQ 密码。
- 在后台确认群聊能力、测试成员和测试群，按平台当前流程把机器人加入目标测试群。正式使用范围与审核要求以后台显示为准。
- 默认通过 WebSocket 主动连接平台；普通图片使用本地上传通道。本项目不要求购买图床、配置图片域名或给家庭路由器做端口映射。
- 如果后台要求服务器 IP 白名单，需要填写**笔记本当前网络的出口公网 IP**。家庭宽带 IP 变化后需要更新。这是 QQ 平台的接入要求，不能通过本地代码保证省略。
- 第一版按 `@机器人 + 指令` 被动回复。主动推送、定时刷群、按钮和 Markdown 消息不在本版范围。
- `allowedGroupIds` 留空表示允许机器人已经加入且平台会推送事件的群；若填写，要使用平台的 `group_openid`，不是普通数字群号。

### Bungie

按照 [Bungie 应用注册说明](https://github.com/Bungie-net/api/wiki/Bungie.net-Application-Portal) 注册应用，复制 API Key 到 `bungie.apiKey`。当前只读公开资料，不需要提供游戏账号密码，也未实现 OAuth 私人资料授权。

## 武器与 Perk 图片

- `武器 雷神`：官方武器大图、基础属性条、固有特性和候选词条图标，完整合成一张图片。
- `武器 自制`：展示对应版本的完整词条池；同名武器优先展示有图样的版本，每页一个版本。用 `武器 自制 第2页` 切换，或直接用武器编号查询。可锻造类型标记来自图样记录，不代表当前账号已经解锁。
- `Perk 狂暴`：普通 / 强化版本分别展示图标和官方说明。完整名称优先精确匹配，没有精确匹配时再模糊搜索，每页最多六条。只收录武器插槽中的有效词条，不混入同名试炼奖励；完全重复的定义合并。
- 词条池由官方插槽和 PlugSet 定义生成，普通 / 强化选项在武器图中合并标记。它不是装备实物的 roll；当前掉落规则可能与收藏中的历史版本不同。
- 武器图自动显示 Starside 的 Aegis / 小棒猪评级、推荐词条标记和 Aegis 大师杰作建议。蓝色表示 Aegis、绿色表示小棒猪、金色表示双方推荐。按武器编号匹配，同名的不同版本分别处理；普通 / 强化图标沿用同一推荐。部分评级由原站按同系列共享，图片会注明。
- 推荐来自公开页面的数据文件，按查询触发刷新，缓存 24 小时；更新失败时最多使用七天内的缓存并注明获取时间。没有缓存或版本未收录时显示提示，仍可查看官方武器资料。它不是 Starside 承诺稳定的公开 API，若页面数据结构变更需更新适配。数据缓存仅存于被 Git 忽略的 `data/starside-recommendations.json`。不复制作者长篇评语，也不把作者的 PVE 刷取评级转换成 PVP 推荐。
- 布局参考 [Starside 装备库](https://starside.work/weapons/index.html) 的资料台形式，图片由机器人本机 HTML 渲染，不依赖该网站截图。游戏图片与基础属性来自 Bungie；社区推荐标注 Starside 与原作者，不包含社区实测的隐藏数值。

## 绑定与锻造进度

1. 在群里 **@机器人 绑定 你的Bungie名称#1234**，使用 Bungie 名称和四位编号。
2. 绑定成功后，直接发送 **@机器人 玩家**、**@机器人 锻造** 或 **@机器人 可锻造**。
3. 默认展示全部图样，先按突袭、地牢、赛季 / 篇章等来源分组，每组优先排列收集中的图样。可发送 `锻造 进行中`、`锻造 未解锁`、`锻造 武器名称` 或 `锻造 副本名` 筛选。

长图采用 Bungie 官方武器图标、活动背景和赛季背景：金框表示图样已解锁，青色表示正在收集，缺失进度保留为未知。分组使用官方来源字段；突袭收藏证章用于补足旧武器 / 重发武器的来源，只有发布标记与明确赛季来源一致时才补足赛季归属，无法确定的单列“来源待确认”。分组表示原始来源或发布归属，不等同于当前完整掉落表；中文分组目前针对简体中文数据库。

图片从 Bungie 官方静态目录下载，缓存在 `data/assets/`，不需要图床。首次查询可能稍慢；图片失败会保留图样和进度，并显示提示，后续查询会重试。长图在 4.5 MB 内按质量压缩，不静默删减武器；若将来数据超出高度 / 大小上限，会提示按副本筛选。

绑定按应用、会话和发送者隔离；当前群内每个人独立保存。跨群或私聊需要分别绑定，避免不同范围的 QQ 标识被错误合并。重新发送绑定指令可更换账号；查询失败不会覆盖旧绑定。`解绑` 只移除自己在当前会话的记录。

绑定持久化在本机 `data/bindings.json`，重启后仍有效。此文件包含 Bungie 查询账号，Git 会忽略整个 `data/`；迁移自己的机器人时可私下保留该文件。它保存的是公开资料的默认查询账号，不是 Bungie 登录授权，也不能操作游戏角色。

图样来自官方 Manifest 中的武器模式记录，进度从 Bungie 的公开 Records 组件读取，每个图样使用自己的完成目标。不会把未返回或私密记录当成 0，也不会把同一个图样在多个角色中的记录相加。已解锁表示图样已取得，实际塑形仍需材料和相应游戏权限。账号查询缓存最多 60 秒。

暂不提供武器俗称词典、隐藏 Perk 数值、私人战绩、已锻造武器实例等级或 OAuth 私人资料授权。

## 战绩与守护者报告

绑定后直接发送 `PVP`、`PVE`、`突袭`、`地牢`、`生涯` 等。战绩、生涯、热力图、配装和队伍也支持在后面加完整 Bungie 名称。`PVP 第2页`、`战绩 第2页` 每页 20 场，近期最多五页；突袭 / 地牢的累计表每页 12 条，累计部分可继续翻页。`称号 第2页`、`成就 传说 第2页` 用于记录列表。

- PVP、试炼、铁旗使用紧凑统计报表，取消地图背景；PVE 与副本报告沿用活动背景。缺失字段显示“—”或未公开，不补零。累计战绩可能包含已删除角色，近期记录仅查询现存角色，因此两者范围可能不同。多角色同一对局仅保留一条参与记录，不将击杀和时间重复相加。
- PVP 胜负来自 `standing`，不把“完成一局”当成获胜。累计同时展示 KD、KDA、效率、爆头率、胜率、场均击杀 / 死亡 / 助攻、每分钟击杀、场均得分、总时长、最高单场击杀、连杀、精准击杀纪录、最高得分、平均存活与官方战斗评分。没有提供外部 Elo、当前竞技段位、赛季榜或无暇次数。
- **KDA** 为 `(击杀 + 助攻 / 2) / 死亡`，**效率 KA/D** 为 `(击杀 + 助攻) / 死亡`，两者分开显示；死亡为 0 时分母按 1，累计优先采用官方值。**爆头率** 为精准击杀 / 击杀，这是终结击杀比例，不是射击命中率。武器分类的爆头率使用对应武器类型的击杀作为分母。
- 每页近期 20 场采用表格，逐场列出击杀、死亡、助攻、KD、KDA、效率、精准击杀、爆头率、得分、参与时长和对局编号。按账号与角色匹配对应战报后补充精准击杀与具体武器，最多四个并发请求，有时间预算；失败不影响基本战绩。图片会注明已取得多少场精准数据。近期 KD / KDA 按总击杀、总死亡汇总，爆头率只使用已取得精准数据的对局，不把缺失值记作 0。
- 武器分类列出累计击杀、精准击杀、分类爆头率及占全部击杀比例；近期武器列出本页战报中的前十件具体武器。分模式概览包括竞技、快速游戏、试炼、铁旗与混战。模式可能有包含关系，不相加作总数；接口缺失某模式累计统计时仍显示“—”，即使历史能读到该模式的部分对局。
- 突袭 / 地牢次数按角色及活动编号分别列出，可能包括检查点。最快完成采用官方累计记录，不宣称全程、单人或无暇认证。
- 对局详情从 Bungie 的 HTTPS 战报服务读取；`上一局` 无需复制编号。战报未生成、未公开、服务故障时返回提示图。
- 热力图只覆盖每个现存角色最近 100 条活动中的近 91 天。空白表示样本里无记录，不能据此认定当天没玩。
- 配装是当前装备实例，不是游戏内保存的配装槽。不切换装备、不操作背包。队伍数据可能延迟，缺失不代表单人游玩。
- 成就与收藏尊重隐藏 / 未揭晓标志，未知状态不当成未完成；角色级成就不把多个角色进度相加。称号的可装备状态采用官方标志。
- `周报` 是官方当前公开里程碑列表，缓存五分钟；不包含完整社区整理、个人巅峰完成情况、商人库存或掉落表。

个人查询缓存最多 60 秒，单局战报缓存五分钟。机器人无需登录游戏账号；资料未公开时需调整 Bungie 隐私设置，或等待未来的 OAuth 功能。本机预览可以使用 `node scripts/local-demo.js "PVE 名称#1234"`，不会向 QQ 群发消息。

## 实时榜的统计规则

- 默认连接斗鱼 6657 房间，先从公开页面解析真实房间编号，再持续收集普通聊天弹幕；查询时生成榜单，不逐条转发到 QQ。展示房间号不能直接当弹幕订阅 ID。
- 默认窗口 5 分钟、前 20 条。可在 `douyu.windowMinutes` 设置 1–30 分钟，在 `topN` 设置 1–30。
- 同一弹幕 ID 只计一次；标准化全角/半角、大小写和空白后合并相同文字。不会把不同句子的“意思”交给大模型合并。
- 优先按不同参与账号数排序，再按出现次数排序，避免一个账号的连续刷屏直接占据第一。参与账号只在内存中用于去重，不展示昵称、不存聊天记录。
- `blockedWords` 可配置不希望展示的词，例如 `["广告词"]`。默认空数组，无自动广告识别。
- 只承诺统计实际收到的样本。重启/重连后从零开始，未收满完整窗口时图片明确提示。超过内存消息上限时显示部分样本提示。
- 连接断开时显示状态图，不展示旧热榜。长期无服务端回应会重连。没有收到弹幕不能直接推断主播是否开播。
- 网站热门榜的计数是**网站复制次数**，与直播间出现次数分开标注。

## Windows 日常运行

- 保持 `03-start.cmd` 窗口打开。按 Ctrl+C 停止；关闭窗口也会结束机器人。
- 在 Windows 电源设置中将“接通电源时进入睡眠”设为“从不”；如果要合上盖子运行，将接通电源时的合盖操作设为“不采取任何操作”。关闭屏幕不影响程序运行，睡眠、休眠、关机和断网会影响。
- 同一目录只能启动一个实例，以免重复回复。QQ 和斗鱼短暂断线会重连；凭证失效、平台禁用或严重错误需要检查后重新启动。
- `logs/` 保留最近 14 天的运行日志，不写密钥、QQ 消息正文、Bungie 玩家查询内容或原始弹幕。建议先在一个测试群验证再扩大使用。
- 本版没有自动修改电源设置、建立开机启动项、开放系统端口或在当前电脑登录 QQ。

## 排查

双击 **06-check.cmd** 检查图片生成、6657 三种接口、Bungie Manifest、命运 2 本地数据库和斗鱼连接。它不验证 QQ AppSecret，也不向群里发消息。

| 现象 | 处理 |
|---|---|
| 找不到 Node / npm | 安装 Node.js 24 LTS，重新打开脚本；确认安装时包括 npm 与 PATH |
| 浏览器下载失败 | 检查目标笔记本网络，重新运行 `01-install.cmd` |
| 找不到命运 2 数据库 | 填写 Bungie API Key，运行 `05-sync-destiny.cmd`，重启机器人 |
| QQ 连接失败 | 检查 AppID / AppSecret、平台启用/审核/沙箱状态、IP 白名单、网络 |
| 已连接但群里无回复 | 确认机器人加入的是平台配置的测试群、发消息者属于测试范围，并 @机器人；若配置了 allowedGroupIds，检查 openid |
| QQ 图片发送失败 | 查看日志错误码；检查平台群聊媒体权限、上传额度、内容审核和网络。上传失败无法保证再发一张错误图 |
| 6657 接口维护/限流 | 稍后重试；热门与搜索缓存 60 秒，接口变更需要更新适配 |
| 实时连接失败 | 检查网络是否放行斗鱼 WebSocket；运行连接检查。网站热门接口可用不代表弹幕端口也可用 |
| 启动提示已有实例 | 先找现有窗口。只有确认没有实例运行时，才删除 `data/bot.lock` 后重试 |

## 技术与数据来源

- Node.js ESM；腾讯官方 `@tencent-connect/qqbot-nodejs` SDK；`douyudm`；Playwright Chromium 本地截图。
- [腾讯 SDK 图片上传](https://github.com/tencent-connect/qqbot-nodejs/blob/main/USAGE.md)：仅发送原生富媒体图片，引用触发查询的消息 ID；长内容最多三张。
- [Bungie 官方 API](https://bungie-net.github.io/multi/index.html)：Manifest 与公开角色查询。物品资料采用简体中文 `zh-chs`，也支持 `zh-cht` / `en`。
- [Bungie 图样记录定义](https://bungie-net.github.io/multi/schema_Destiny-Definitions-Records-DestinyRecordDefinition.html)与[记录进度](https://bungie-net.github.io/multi/schema_Destiny-Components-Records-DestinyRecordComponent.html)：使用 `CraftingRecipeUnlocked` 类型记录和账号公开进度，不向游戏执行塑形操作。
- [sb6657 项目](https://github.com/sb6657-cn/sb6657)与[接口说明](https://github.com/sb6657-cn/sb6657/blob/master/AI_GUIDE.md)：第三方调用不携带官网来源统计头，不调用提交/投票等写入接口。
- [douyudm](https://github.com/flxxyz/douyudm)：斗鱼 WebSocket 数据接收。实时接入依赖平台与当地网络，不保证平台提供全量数据。

开发检查：`npm test`；离线图片预览：`npm run preview`；连接检查：`npm run doctor`。
依赖版本通过 `package-lock.json` 固定，复制到新电脑后用 `01-install.cmd` 安装。`config.json`、`data/`、`logs/`、`output/`、`node_modules/` 和 `.local-browsers/` 均由 Git 忽略。
